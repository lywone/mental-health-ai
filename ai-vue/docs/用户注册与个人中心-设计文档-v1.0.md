## 1. 背景与目标

当前用户端采用「免登录」模式：进入用户端自动调用 `/api/auth/user/dev-login`，由后端取最小 ID 用户（或创建默认用户"小林"）签发 JWT，用户无感知。该模式无法区分真实用户，无法支撑"AI 咨询需登录"的要求，也没有注册与个人信息管理能力。

本设计目标：

1. AI 咨询入口增加登录校验，未登录跳转普通用户登录页；
2. 新增普通用户注册（手机号 + 验证码），管理后台注册暂不放开；
3. 注册仅必填手机号 + 验证码，其余信息暂不填；
4. 新增用户基本信息配置页面。

## 2. 需求清单（新增 FR-U 系列）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-U01 | AI 咨询入口登录校验：未登录访问 /chat 跳转普通用户登录页，登录后回跳原页 | P0 |
| FR-U02 | 普通用户登录：手机号 + 短信验证码登录 | P0 |
| FR-U03 | 普通用户注册：手机号 + 短信验证码，昵称等其余信息选填（可暂不填） | P0 |
| FR-U04 | 短信验证码发送 + 频控（60s 间隔、有效期、防爆破） | P0 |
| FR-U05 | 用户基本信息配置页：昵称、头像、性别、生日、简介 | P1 |
| FR-U06 | 管理端注册入口：暂不放开（不做） | — |
| FR-U07 | dev-login 降级为联调开关（默认关闭，dev 环境可开） | P1 |

## 3. 现状与差距分析

### 3.1 现状（与本需求相关的关键点）

| 位置 | 现状 | 与本需求的冲突 |
|------|------|----------------|
| [UserLayout.vue:54-65](../src/components/UserLayout.vue) | `onMounted` 无登录态时自动 `userDevLogin()` | 用户永远"已登录"，FR-U01 无法生效 |
| [http.js:40-53](../src/api/http.js) | user 请求 401 → 自动 dev-login 换 token 重试 | 未登录被静默替换成 dev 用户，掩盖真实登录态 |
| [router/index.js:45-55](../src/router/index.js) | 守卫只保护 `/back/*`，用户端全放行 | 无用户端登录跳转逻辑 |
| [AuthController.java](../../ai-serve/src/main/java/com/mental/health/module/auth/AuthController.java) | 仅有 `admin/login`、`user/dev-login` | 无注册、验证码登录、用户信息接口 |
| `t_user` 表（init.sql） | `id/nickname/avatar/phone(唯一)/status` | 缺 gender/birthday/bio，基本信息配置无字段可存 |
| 依赖 | pom 已含 Redis、Spring Security、Validation | 验证码存储/频控无需新增依赖 |

### 3.2 结论

- 手机号在 `t_user` 已存在且唯一，注册即"手机号落库 + 验证码校验"，表改动小；
- 必须改造两处"自动 dev-login"，否则登录判断形同虚设；
- 短信通道、验证码服务为全新模块。

## 4. 总体方案

### 4.1 核心决策

1. **下线静默 dev-login**：用户端登录态完全由真实登录（验证码登录/注册）建立；
2. **dev-login 保留为开关**：`auth.dev-login-enabled: false`（默认关，application-dev.yml 置 true 供联调），避免联调/演示时被卡死；
3. **登录与注册分开两个 Tab**（语义清晰，符合"添加注册功能"的诉求）：同一手机号，登录 Tab 未注册提示去注册，注册 Tab 已注册提示去登录；注册成功自动登录（直接下发 token）；
4. **用户端全部页面要求登录**（不只 /chat）：因为情绪日志、知识库等接口均为 user scope，未登录请求必然 401。守卫层面对 UserLayout 子路由统一校验，AI 咨询（FR-U01）是需求触发点，实现上自然覆盖。

### 4.2 主流程

```
用户点击「AI咨询」(/chat)
        │
        ▼
路由守卫：isUserLogin()？
        │ 否                          │ 是
        ▼                             ▼
跳转 /user/login?redirect=/chat     正常进入 AI 咨询
        │
        ▼
登录页（Tab：登录 / 注册）
  ├─ 登录：手机号 → 获取验证码 → 提交 → 后端校验 → 发 token
  └─ 注册：手机号 → 获取验证码 → 提交(昵称选填) → 后端建号 → 发 token
        │
        ▼
登录/注册成功：setUserLogin() → 回跳 redirect（默认 /chat 或来源页）
```

### 4.3 后端处理链路

```
POST /api/auth/user/sms/send {phone, scene}
  → 频控校验（60s/次、每日≤10条）→ 生成6位码 → 存 Redis(5min) → SmsSender 发送

POST /api/auth/user/register {phone, code, nickname?}
  → 验证码校验（错误5次锁30min）→ 手机号未注册校验 → 插入 t_user（默认昵称）→ 签发 JWT → 删除验证码（一次性）

POST /api/auth/user/login {phone, code}
  → 验证码校验 → 查 t_user（不存在→"该手机号未注册"；status=0→"账号已禁用"）→ 签发 JWT

GET/PUT /api/user/profile   ← uid 取自 CurrentUser，只能操作本人
POST /api/user/upload/avatar ← 复用现有本地存储（storage.upload-dir）
```

## 5. 后端设计（ai-serve）

### 5.1 表结构变更

```sql
-- 增量脚本（同时更新 init.sql 保持新装环境一致）
ALTER TABLE t_user
    ADD COLUMN gender   TINYINT      NULL COMMENT '0 保密 / 1 男 / 2 女' AFTER avatar,
    ADD COLUMN birthday DATE         NULL COMMENT '生日' AFTER gender,
    ADD COLUMN bio      VARCHAR(200) NULL COMMENT '个人简介' AFTER birthday;
```

- `phone` 已有 `UNIQUE KEY uk_phone`，注册并发冲突捕获 `DuplicateKeyException` 返回"手机号已注册"；
- 不新增表：验证码放 Redis，不落库。

### 5.2 新增接口契约（沿用 `{code, message, data}`）

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/api/auth/user/sms/send` | 匿名 | 发送验证码，scene: `LOGIN` / `REGISTER` |
| POST | `/api/auth/user/register` | 匿名 | 注册并自动登录 |
| POST | `/api/auth/user/login` | 匿名 | 验证码登录 |
| GET | `/api/user/profile` | 用户 | 查询本人信息 |
| PUT | `/api/user/profile` | 用户 | 更新本人信息 |
| POST | `/api/user/upload/avatar` | 用户 | 头像上传（复用 admin 上传的存储实现） |

**示例：发送验证码**

```json
// 请求
{ "phone": "13812345678", "scene": "REGISTER" }
// 响应 data（生产环境不回显验证码）
{ "intervalSeconds": 60 }
// dev 通道（sms.channel=log 且 dev 模式）额外返回 devCode 便于联调
{ "intervalSeconds": 60, "devCode": "123456" }
```

**示例：注册（登录同构）**

```json
// 请求
{ "phone": "13812345678", "code": "123456", "nickname": "" }
// 响应 data：与现有 dev-login 返回结构一致，前端 setUserLogin() 无需适配
{ "token": "...", "tokenType": "Bearer", "expiresIn": 86400,
  "profile": { "id": 12, "nickname": "用户5678", "avatar": null } }
```

**示例：个人信息**

```json
// GET /api/user/profile → data
{ "id": 12, "phone": "138****5678", "nickname": "用户5678", "avatar": "/upload/xx.png",
  "gender": 1, "birthday": "2000-01-01", "bio": "希望睡个好觉", "createdAt": "2026-10-27 10:00:00" }
// PUT 请求体（均可选，只更新传入字段）
{ "nickname": "小暖", "avatar": "/upload/xx.png", "gender": 1, "birthday": "2000-01-01", "bio": "..." }
```

校验规则：

- 手机号：`^1[3-9]\d{9}$`（后端 `@Pattern` + 前端表单校验双保险）；
- 昵称：≤20 字，去空格后为空则用默认昵称"用户"+手机号后 4 位；
- bio ≤200 字；gender ∈ {0,1,2}；birthday 合法日期且不晚于今天。

### 5.3 验证码服务（VerifyCodeService，Redis）

| 项 | 设计 |
|----|------|
| 存储 | `sms:code:{phone}` → 6 位数字，TTL 5 分钟 |
| 发送间隔 | `sms:interval:{phone}` TTL 60s，存在则拒绝（提示"请稍后再试"） |
| 每日上限 | `sms:limit:{phone}:{yyyyMMdd}` 计数 ≤10，超限拒绝 |
| 校验失败锁定 | `sms:fail:{phone}` 计数，≥5 次锁 30 分钟 |
| 一次性 | 校验通过立即删除，注册/登录共用但 scene 隔离（`sms:code:{scene}:{phone}`） |

### 5.4 短信通道抽象

```java
public interface SmsSender { void send(String phone, String code, String scene); }
```

- `LogSmsSender`（默认）：验证码打印到日志；dev 模式下接口回显 `devCode`；
- `AliyunSmsSender` / `TencentSmsSender`：预留骨架，按配置 `sms.channel` 装配，一期不实现真实发送；
- 配置（application.yml）：

```yaml
sms:
  channel: log        # log / aliyun / tencent
  code-ttl-seconds: 300
  send-interval-seconds: 60
  daily-limit: 10
```

### 5.5 Security 配置与 dev-login 开关

- `SecurityConfig` 放行（permitAll）：`/api/auth/user/sms/send`、`/api/auth/user/register`、`/api/auth/user/login`；`/api/auth/user/dev-login` 改为按开关放行/404；
- `auth.dev-login-enabled=false`（application.yml 默认），application-dev.yml 覆盖为 true；
- JWT 沿用现有 `JwtUtil`（uid/role=USER），`JwtAuthFilter` 无需改动。

### 5.6 新增/改动类清单

| 层 | 类 | 动作 |
|----|-----|------|
| auth | `UserAuthController` | 新增：sms/send、register、login |
| auth | `AuthService` | 新增 register/login 方法；devLogin 加开关判断 |
| auth | `SmsService` / `VerifyCodeService` / `SmsSender`(接口) / `LogSmsSender` | 新增 |
| user | `UserProfileController` | 新增：GET/PUT profile、upload/avatar |
| user | `UserService`、`User` 实体 | 实体加 gender/birthday/bio，新增更新方法 |
| config | `SecurityConfig`、`JwtUtil`(不动) | 放行清单调整 |
| resources | `application.yml` / `application-dev.yml` / `init.sql` + 增量 SQL | 配置与表变更 |

## 6. 前端设计（ai-vue）

### 6.1 路由与守卫

```
新增路由：
/user/login   name: user-login   UserAuth.vue   （独立全屏页，不套 UserLayout）
/user/profile name: user-profile Profile.vue    （UserLayout 子路由，meta.title: 个人中心）

router/index.js 守卫改造：
- UserLayout 子路由统一 meta: { requiresUserAuth: true }
- beforeEach：to.matched.some(r => r.meta.requiresUserAuth) && !isUserLogin()
  → return { path: '/user/login', query: { redirect: to.fullPath } }
- /user/login 且已登录 → redirect 回跳
- /back/* 管理员守卫保持不变（两套登录态互不干扰）
```

AI 咨询（FR-U01）：/chat 属 UserLayout 子路由，统一被守卫覆盖；用户从首页/导航点击"AI咨询"未登录时即跳登录页，登录成功回跳 /chat。

### 6.2 页面设计

**UserAuth.vue（登录/注册页）**

- 风格复用 [Login.vue](../src/views/Login.vue)：全屏浅灰底 + 居中白卡，品牌区文案改为"用户端"；
- 两个 Tab：登录 / 注册；
- 字段：手机号（11 位校验）、验证码（输入框 + "获取验证码"按钮，60s 倒计时禁用）、注册 Tab 增加选填昵称；
- "获取验证码"前置校验手机号格式，避免无效请求；
- 提交成功：`setUserLogin(res)` → `router.push(route.query.redirect || '/')`；
- 顶部提供"管理员登录"小链接跳 /login（可选，评审确认）。

**Profile.vue（个人中心）**

- 布局：居中卡片表单（参考用户端现有页面风格，max-width 560px）；
- 头像：圆形预览 + 点击上传（el-upload，调 `/api/user/upload/avatar`，5MB/图片类型限制）；
- 字段：昵称（必填 ≤20）、性别（单选：保密/男/女）、生日（el-date-picker）、简介（textarea ≤200 带字数统计）、手机号（只读展示，脱敏）；
- 保存：PUT /api/user/profile → 成功后同步更新本地 `user_auth.profile`（UserLayout 头部昵称即时刷新），ElMessage 提示；
- 入口：UserLayout 右上角用户区，头像+昵称可点击进入。

### 6.3 auth.js / http.js 改造

- `auth.js`：结构不动（`user_auth` 双轨沿用），`setUserLogin` 的 profile 结构扩展为 `{id, nickname, avatar, phone}`；
- `http.js`：
  - **删除** `requestWithUserRelogin` 的自动 dev-login 重试，改为与管理端对称的 401 处理：清 `user_auth` → `window.location.href = /user/login?redirect=...`；
  - 匿名接口（sms/send、register、login）请求时带 `scope: 'user'` 但不携带 token（现有 rawRequest 已支持 `token: null`）。

### 6.4 UserLayout 改造

- 删除 `onMounted` 自动 dev-login 逻辑（FR-U07：dev 环境联调可在 dev 工具里手动调，或依赖 dev-login 开关接口）；
- 导航 `navItems` 不变（个人中心走右上角头像入口，不占主导航）；
- 用户区：未登录显示"请登录"链接 → /user/login；已登录显示头像（无头像用首字符占位）+ 昵称，点击下拉：个人中心 / 退出登录。

### 6.5 api/index.js 新增

```js
export const userSmsSend = (phone, scene) => post('/api/auth/user/sms/send', { phone, scene }, { scope: 'user', anonymous: true })
export const userRegister = (phone, code, nickname) => post('/api/auth/user/register', { phone, code, nickname }, { scope: 'user', anonymous: true })
```

## 7. 决策点（待评审确认）

| # | 问题 | 建议 |
|---|------|------|
| Q1 | 用户端是否允许游客浏览（首页/知识库）？本设计为"统一需登录"，因其余接口均需 token | 统一需登录（最简、安全）；如要游客浏览，需后端放行文章接口并做匿名降级，二期再议 |
| Q2 | 登录/注册是否合并为"验证码即登录、未注册自动注册"？ | 不合并，Tab 分开（明确满足"注册功能"诉求，产品语义清晰） |
| Q3 | dev-login 去留 | 保留 + 配置开关（默认关），避免破坏现有联调脚本 |
| Q4 | 个人中心字段范围 | 昵称/头像/性别/生日/简介；手机号一期只读（换绑涉及验证码双通道，二期） |
| Q5 | 短信服务商 | 一期 Log 通道 + 接口抽象；真实通道需甲方提供签名/模板/密钥后接入 |
| Q6 | 存量用户（含"小林"）无手机号，无法验证码登录 | 保留数据不动；管理员后台后续可做手机号补录（不在本期） |

## 8. 测试要点

1. 未登录直接访问 /chat、/moods、/articles → 均跳 /user/login?redirect=原路径，登录后回跳；
2. 注册：非法手机号 / 错误验证码 / 过期验证码 / 已注册手机号 / 并发同手机号注册（唯一键冲突）；
3. 验证码：60s 内重复发送被拒、单日超 10 条被拒、5 次校验失败锁定 30min、验证通过后验证码失效（不可复用）；
4. 登录：未注册手机号提示、禁用账号（status=0）提示、token 有效期内不再跳登录；
5. 401 链路：token 过期后任意用户端请求 → 清登录态跳登录页（不再静默 dev-login）；
6. 个人中心：仅能读/改本人信息（伪造 uid 不可行，uid 取自 token）；头像超 5MB/非图片被拒；保存后导航栏昵称即时更新；
7. 管理端回归：/back/* 守卫与管理员登录不受影响；dev-login 开关关闭后旧脚本失效需知会。
