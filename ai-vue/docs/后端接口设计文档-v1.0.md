## 1. 概述

当前前端为纯 Mock 实现：所有数据来自 `src/mock/data.js` 内存数组，登录为前端假登录（`localStorage`）。本文档定义一套 Java 后端 RESTful 接口，**字段命名与业务口径与 Mock 一一对应**，使前端可以按模块逐步替换 Mock 为真实接口。

设计原则：

1. **口径对齐**：统计口径、枚举值、字段名与前端 Mock 完全一致（如文章状态直接使用 `草稿 / 已发布 / 已下架`），前端改动最小化。
2. **前后端分离**：JWT 无状态认证，后台接口与用户端接口按角色隔离。
3. **可演进**：AI 对话预留 SSE 流式与会话评分；用户端登录预留正式方案（当前提供开发登录）。

### 2.3 通用接口规范

| 项 | 约定 |
| --- | --- |
| Base URL | `/api` |
| 认证 | 请求头 `Authorization: Bearer <token>`；公开接口见 5.1 |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`，时区 GMT+8 |
| 日期格式 | `yyyy-MM-dd`（筛选参数） |
| 图表日期 | `MM-dd`（与前端 ECharts X 轴一致） |
| ID | 数据库 BIGINT 自增；Mock 中 `U1001/M0001` 等为演示编码，上线后直接使用数字 id 展示 |
| 枚举 | **接口层统一使用前端现有中文字符串**（如 `status: "已发布"`），数据库存 TINYINT，VO 层转换 |
| Content-Type | `application/json;charset=UTF-8`（上传除外） |

统一响应体 `Result<T>`：

```json
{ "code": 0, "message": "success", "data": { } }
```

- `code = 0` 成功；非 0 为业务错误码（见 2.5），HTTP 状态码除 401/403/500 外统一 200。
- 列表分页统一返回 `PageResult<T>`：

```json
{ "list": [], "total": 0, "page": 1, "pageSize": 10 }
```

分页参数：`page`（默认 1）、`pageSize`（默认 10；与前端分页器 10/20/50 对应）。

### 2.4 角色与鉴权

| 路径前缀 | 角色 | 说明 |
| --- | --- | --- |
| `/api/auth/**` | 公开/半公开 | 登录、登出 |
| `/api/admin/**` | `ADMIN` | 管理后台，路由对应 `/back/*` |
| `/api/user/**` | `USER` | 用户端，路由对应 `/*` |
| `/api/common/**` | 登录即可 | 字典等 |

鉴权失败返回：`1002 未登录或 token 无效`、`1003 登录已过期`、`1004 无权限访问`。前端拦截 1002/1003 时清除本地登录态并跳转 `/login`（后台）。

### 2.5 错误码表

| code | 含义 |
| --- | --- |
| 0 | 成功 |
| 1001 | 账号或密码错误 |
| 1002 | 未登录或 token 无效 |
| 1003 | 登录已过期 |
| 1004 | 无权限访问 |
| 1101 | 参数校验失败（message 带字段明细） |
| 1102 | 数据不存在 |
| 1201 | 会话不存在或无权限 |
| 1202 | 消息内容超长（>500 字） |
| 1203 | 情绪标签非法（不在白名单） |
| 1204 | 评分超出范围（1-10） |
| 1301 | 文件类型不支持 |
| 1302 | 文件超出大小限制 |
| 1501 | AI 服务暂时不可用（已返回兜底回复） |
| 500 | 系统内部错误 |

### 5.1 认证模块

#### ① POST /api/auth/admin/login — 管理员登录

对应前端 `Login.vue`（预置账号 admin/123456）。

请求体：

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| username | string | 是 | 1-50 |
| password | string | 是 | 1-64 |

响应 `data`：

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "tokenType": "Bearer",
  "expiresIn": 7200,
  "admin": { "id": 1, "username": "admin", "nickname": "管理员" }
}
```

说明：JWT HS256，有效期 2h（可配置），Redis 保存 `token → adminId` 用于登出吊销与过期判断。连续失败 5 次锁定 10 分钟（Redis 计数）。

#### ② POST /api/auth/admin/logout — 退出登录

请求头携带 token，服务端将其加入 Redis 黑名单。响应 `data: null`。

#### ③ GET /api/auth/admin/me — 当前管理员信息

响应 `data`：`{ "id": 1, "username": "admin", "nickname": "管理员" }`

#### ④ POST /api/auth/user/dev-login — 用户端开发登录

前端当前无用户登录页、固定使用用户 U1001（见 `user/Chat.vue` 的 `ME = 'U1001'` 与 `auth.js` 的 `setUserLogin`）。为不阻塞联调，提供开发登录；正式版替换为手机验证码/微信登录，响应结构保持不变。

请求体（均可选）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| userId | long | 指定用户；缺省返回默认用户（昵称「小林」，对应 Mock U1001） |

响应 `data`：

```json
{
  "token": "eyJ...",
  "tokenType": "Bearer",
  "expiresIn": 86400,
  "user": { "id": 1, "nickname": "小林" }
}
```

### 5.2 数据分析（对应 `/back/dashboard`）

#### ⑤ GET /api/admin/dashboard/stats — 统计卡片

对应 Mock `getStats()`（FR-D01）及页面内「平均时长」。

响应 `data`：

| 字段 | 类型 | 口径 |
| --- | --- | --- |
| totalUsers | int | 用户总数 |
| activeUsers | int | 近 7 天有情绪记录或咨询会话的去重用户数（Mock Q3 口径） |
| totalMoods | int | 情绪日志总数 |
| moodsToday | int | 今日新增情绪日志 |
| totalConsults | int | 咨询会话总数 |
| consultsToday | int | 今日新增会话 |
| avgScore | decimal(3,1) \| null | 全部情绪记录平均分，1 位小数；无记录为 null |
| avgDurationMin | decimal(5,1) \| null | 已结束会话时长均值（分钟），1 位小数；无记录为 null |

#### ⑥ GET /api/admin/dashboard/trends — 三条趋势

Query：`days`（默认 30，最大 90）。

响应 `data`（三条序列的 `date` 均为 `MM-dd`、按时间升序、长度 = days）：

```json
{
  "emotionTrend":   [ { "date": "10-01", "avgScore": 6.5, "count": 2 } ],
  "consultTrend":   [ { "date": "10-01", "count": 1, "userCount": 1 } ],
  "activityTrend":  [ { "date": "10-01", "activeUsers": 2 } ]
}
```

口径说明：

- `emotionTrend.avgScore`：当日情绪记录平均分（1 位小数），**当日无记录为 null**（前端 `connectNulls: true` 已处理断点）；`count` 为当日记录条数。
- `consultTrend`：当日会话数与参与去重用户数。
- `activityTrend.activeUsers`：当日有情绪记录或会话的去重用户数（Mock Q4 占位口径）。

实现建议：单条 SQL 按天聚合（`DATE(created_at)` GROUP BY），可加 Redis 缓存 60s。

### 5.3 文章管理（对应 `/back/articles`）

#### ⑦ GET /api/admin/articles — 分页列表

Query 参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| keyword | string | 否 | 标题模糊匹配 |
| category | string | 否 | 分类（4.1 中文枚举） |
| status | string | 否 | 草稿 / 已发布 / 已下架 |
| page / pageSize | int | 否 | 默认 1 / 10 |

响应 `PageResult<ArticleVO>`，`ArticleVO`（列表不含正文）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | long | |
| title | string | |
| category | string | |
| cover | string | 封面 URL，可为 "" |
| summary | string | |
| status | string | 中文枚举 |
| views | int | |
| publishTime | string \| null | `yyyy-MM-dd HH:mm:ss` |
| createdAt / updatedAt | string | |

#### ⑧ GET /api/admin/articles/{id} — 详情

响应 `ArticleVO` + `content`（正文全文）。不存在返回 `1102`。

#### ⑨ POST /api/admin/articles — 新增

请求体：

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| title | string | 是 | ≤50 字 |
| category | string | 是 | 分类白名单 |
| cover | string | 否 | 封面 URL（先调 ⑬ 上传） |
| summary | string | 否 | ≤100 字；为空时由前端展示正文前 50 字 |
| content | string | 是 | 正文纯文本 |

行为：`status` 固定写入 `草稿`，`views=0`，`publishTime=null`（与前端「新增默认草稿」一致）。响应 `data`：新建后的 `ArticleVO`。

#### ⑩ PUT /api/admin/articles/{id} — 编辑

请求体同 ⑨（全量更新）。任意状态可编辑（与前端行为一致）。响应：更新后 `ArticleVO`。

#### ⑪ DELETE /api/admin/articles/{id} — 删除

物理删除（前端已二次确认，提示「删除后不可恢复」）。响应 `data: null`。

#### ⑫ PUT /api/admin/articles/{id}/status — 发布 / 下架

请求体：`{ "action": "publish" | "offline" }`

| action | 前置状态 | 行为 |
| --- | --- | --- |
| publish | 草稿 / 已下架 | 置为 `已发布`；若 `publishTime` 为空则写当前时间（与前端一致，下架后重新发布不改首次发布时间） |
| offline | 已发布 | 置为 `已下架`，`publishTime` 保留 |

幂等：重复操作直接返回成功。响应：更新后 `ArticleVO`。

#### ⑬ POST /api/admin/upload/image — 封面图上传

`multipart/form-data`，字段 `file`。限制：jpg/png/webp，≤5MB，违规返回 `1301/1302`。

响应 `data`：`{ "url": "https://.../cover/xxx.png" }`（v1 存本地磁盘/静态映射，配置可切 OSS）。

响应 `data`：结构同 ⑮ GET /api/admin/consultations/{id}（会话 VO + `messages[]`）。

#### ⑳ POST /api/user/chat/messages — 发送消息（核心）

对应前端 `send()` 流程：无会话时自动建会话（`createSession`），随后取 AI 回复（`mockAiReply`）。

请求体：

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| sessionId | long | 否 | 为空 → 新建会话；非空须属于当前用户且未结束 |
| content | string | 是 | 1-500 字（前端 maxlength=500） |

处理流程（事务内写库，AI 调用在外）：

1. `sessionId` 为空则创建会话（status=进行中，start_time=now）。
2. 保存用户消息，`message_count + 1`。
3. 危机词检测（见 6.1）：命中 → 返回固定干预话术，`risk_flag=1`。
4. 调用 LLM：System Prompt（人设「小暖」） + 最近 10 条历史消息 + 当前输入。
5. 保存 AI 回复，`message_count + 1`。超时（5s）或异常 → 兜底语料顺序轮换（与 Mock `AI_FALLBACK_REPLIES` 相同文案），`code=0` 正常返回。

响应 `data`：

```json
{
  "sessionId": 102,
  "userMessage": { "from": "user", "time": "2026-10-26 19:02:10", "text": "今天有点累" },
  "reply": { "from": "ai", "time": "2026-10-26 19:02:13", "text": "听起来你最近承受了很多……" }
}
```

限流：每用户 10 次/分钟（Redis），超出返回 `1101`（message 提示稍后再试）。

#### ㉑ POST /api/user/consultations/{id}/end — 结束会话

幂等。行为：status → 已结束，`end_time=now`，`duration_min = max(1, round((end-start)/60000))`。响应：会话 VO。

#### ㉒ PUT /api/user/consultations/{id}/score — 会话评分（预留）

请求体 `{ "score": 1-10 }`。仅已结束会话可评；写入 `t_consult_session.score`（Mock 中已结束会话有 4-10 评分即来源于此）。v1 前端暂无此交互，接口先行预留。

> 会话自动结束：定时任务每小时扫描「进行中且最后一条消息时间 > 24h」的会话，执行与 ㉑ 相同的结束逻辑。

## 6. 关键设计说明

### 6.1 AI 对话链路

```text
用户消息 → 内容安全/危机词检测 ──命中──→ 固定干预话术 + risk_flag=1 + 告警日志
                │未命中
                ▼
        Prompt 组装（人设 + 最近10条上下文）→ LLM API
                │成功                    │超时/异常(5s)
                ▼                        ▼
          保存 AI 回复              兜底语料轮换返回
```

- **人设 Prompt**：与前端助手一致——名称「宁澄AI助手」、自称「小暖」；温暖共情、多倾听多提问、不给医疗诊断；结尾自然引导。人设文案配置化（`application.yml`），不改代码可调。
- **危机干预**：维护敏感词表（自伤、轻生等）；命中后不走 LLM，返回标准引导语（肯定情绪 + 建议寻求专业帮助/心理援助热线），会话打 `risk_flag=1`，预留人工审核列表。
- **降级语料**：v1 直接复用 Mock 的 7 条规则 + 5 条兜底文案作为离线回复，保证 LLM 不可用时体验不塌方。
- **流式预留**：v1 同步返回即可满足前端「正在输入…」动效；v1.1 增加 `POST /api/user/chat/stream`（SSE，`text/event-stream`），前端用 fetch Reader 渐进渲染。

### 6.2 会话生命周期

```text
新会话(进行中) ──首条消息──→ 进行中 ──用户主动结束/24h无消息自动结束──→ 已结束
                                        └── 评分（可选，预留）
```

- `duration_min` 在结束时计算；进行中会话该字段为 null（前端已做「—」兜底）。
- `messageCount` 冗余存储，写消息与结束会话在同一事务维护。

### 6.3 统计口径汇总（与 Mock 严格对齐）

| 指标 | 口径 |
| --- | --- |
| 活跃用户（卡片） | 近 7 天有情绪记录或会话的去重用户 |
| 活跃度趋势 | 当日有情绪记录或会话的去重用户 |
| 平均情绪 | 全量情绪记录均分，1 位小数，无数据显示 `-` |
| 平均时长 | 仅已结束会话，分钟 1 位小数 |
| 情绪花园 | 今日最新记录 ×10；无今日记录为空 |
| 趋势图 | 缺数日 `avgScore=null`、计数为 0，序列长度固定 |

### 6.4 安全与隐私（心理健康数据属敏感个人信息）

1. 角色隔离：`/api/admin/**` 仅 ADMIN；用户端接口从 JWT 解出 userId，**所有「我的」查询强制按当前用户过滤**，禁止传 userId 查他人。
2. 管理员查看会话消息、情绪日志详情 → 记录审计日志 `sys_audit_log`（操作人、对象、时间），预留导出。
3. 密码 BCrypt；登录失败锁定；登出 token 进 Redis 黑名单。
4. CORS：开发环境放开 `http://localhost:5173`，生产按域名白名单。
5. AI 输入输出均过内容安全检测；数据库敏感字段（会话消息、情绪内容）建议应用层 AES 加密存储（v1.1）。

### 6.5 性能

- Dashboard 聚合查询走日期索引 + Redis 60s 缓存；数据量增大后增加日汇总表 `t_daily_stat`（定时任务预聚合）。
- 文章浏览量原子自增，避免读改写竞态。
- 会话消息查询走 `(session_id, created_at)` 联合索引。
